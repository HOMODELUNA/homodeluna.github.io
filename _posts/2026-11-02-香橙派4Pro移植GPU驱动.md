**Orange Pi 4 Pro BXM-4-64 GPU 驱动编译与验证记录**

> [bobyshamen-arch/pvr-a733: Open-source GPU driver for the Allwinner A733 (PowerVR BXM-4-64): upstream drm/imagination backported to the 6.6 vendor kernel, for Mesa's PowerVR Vulkan driver](https://github.com/bobyshamen-arch/pvr-a733)

本文记录在 Orange Pi 4 Pro（Allwinner A733 / sun60iw2）上，使用
`ref-pvr-a733` 开源驱动栈编译、安装并验证 Imagination PowerVR
BXM-4-64 GPU 的完整过程。

## 2. 安装内核 headers

```bash
sudo dpkg -i /opt/linux-headers-current-sun60iw2_1.1.0_arm64.deb
```

确认构建目录存在：

```bash
ls -l /lib/modules/$(uname -r)/build
```

应指向：

```text
/lib/modules/6.6.98-sun60iw2/build -> /usr/src/linux-headers-6.6.98-sun60iw2
```

> 如果手动解包 deb 而不是用 `dpkg -i`，deb 内预置的
> `scripts/basic/fixdep` / `scripts/mod/modpost` 是 x86-64 二进制，
> 会报 `Exec format error`。需要执行 deb 的 postinst 步骤在本机重建，
> 或直接使用 `dpkg -i` 让 postinst 自动完成。

## 6. 路径陷阱：symbolic link 导致安装被跳过

`/home/homodeluna/ssd` 是 `/mnt/luna-ssd` 的符号链接。

GNU make 的 `CURDIR` 会解析成物理路径，因此 `modules.order` 中记录的是：

```text
/mnt/luna-ssd/src/opi-bxm/ref-pvr-a733/powervr.o
```

如果执行：

```bash
cd /home/homodeluna/ssd/src/opi-bxm/ref-pvr-a733
sudo make -C /lib/modules/$(uname -r)/build M=$PWD modules_install
```

此时 `$PWD` 是 `/home/...`，与 `modules.order` 中的 `/mnt/...` 不一致，
`modules_install` 会匹配不到模块，只执行 `DEPMOD`，不打印 `INSTALL`。
结果就是：

```text
modprobe: FATAL: Module powervr not found
```

解决方法：统一使用物理路径。

```bash
cd /mnt/luna-ssd/src/opi-bxm/ref-pvr-a733
sudo make -C /lib/modules/$(uname -r)/build M=$PWD modules_install
```

或者显式使用 `readlink -f`：

```bash
sudo make -C /lib/modules/$(uname -r)/build \
  M=$(readlink -f /home/homodeluna/ssd/src/opi-bxm/ref-pvr-a733) \
  modules_install
```

## 7. 模块参数

创建 `/etc/modprobe.d/pvr-a733.conf`：

```bash
printf 'options powervr exp_hw_support=1 a733_clk_mhz=600\n' | \
  sudo tee /etc/modprobe.d/pvr-a733.conf
```

内容：

```text
options powervr exp_hw_support=1 a733_clk_mhz=600
```

说明：

- `exp_hw_support=1`：Mesa/驱动只将 `36.52/36.53` 列为 supported，
  BXM-4-64 的 `36.56.104.183` 需要绕过检查。
- `a733_clk_mhz=600`：首次验证使用 600 MHz，稳定后再尝试 800/1008 MHz。

## 11. Mesa 用户态

系统原有 `/usr/share/vulkan/icd.d/img_icd.json` 指向 vendor 的
`/lib/libVK_IMG.so`，该库不存在，且 vendor UAPI 不能配 mainline
`powervr` 驱动。

使用 Debian trixie-backports 的 Mesa 26.1.6：

```bash
sudo apt install -t trixie-backports \
  mesa-vulkan-drivers vulkan-tools libdisplay-info2
```

本机安装版本：

```text
mesa-vulkan-drivers   26.1.6-1~bpo13+1
vulkan-tools          1.4.304.0+dfsg1-1
libdisplay-info2      0.2.0-2
```

禁用不可用的 vendor ICD：

```bash
sudo mv /usr/share/vulkan/icd.d/img_icd.json \
        /usr/share/vulkan/icd.d/img_icd.json.disabled
```

当前 ICD：

```text
/usr/share/vulkan/icd.d/powervr_mesa_icd.json
```

## 12. Vulkan 枚举验证

由于 BXM-4-64 尚未进入 Mesa 的 conformant 列表，需要：

```bash
export PVR_I_WANT_A_BROKEN_VULKAN_DRIVER=1
```

运行：

```bash
PVR_I_WANT_A_BROKEN_VULKAN_DRIVER=1 vulkaninfo --summary
```

本机关键结果：

```text
GPU0:
    apiVersion         = 1.2.354
    driverVersion      = 26.1.6
    vendorID           = 0x1010
    deviceID           = 0x36104183
    deviceType         = PHYSICAL_DEVICE_TYPE_INTEGRATED_GPU
    deviceName         = PowerVR B-Series BXM-4-64 MC1
    driverID           = DRIVER_ID_IMAGINATION_OPEN_SOURCE_MESA
    driverName         = Imagination open-source Mesa driver
    driverInfo         = Mesa 26.1.6-1~bpo13+1
    conformanceVersion = 1.3.8.4

GPU1:
    deviceName         = llvmpipe (LLVM 19.1.7, 128 bits)
    driverID           = DRIVER_ID_MESA_LLVMPIPE
```

说明：

- `GPU0` 是 BXM-4-64 硬件 GPU。
- `GPU1` 是 Mesa 的 CPU 软件渲染器 llvmpipe，属于正常 fallback。
- 如果出现 Intel ANV 的 `VK_ERROR_INCOMPATIBLE_DRIVER` 警告，是因为
  `mesa-vulkan-drivers` 同时安装了 Intel ICD，但系统没有 Intel GPU，
  无害。可禁用：

  ```bash
  sudo mv /usr/share/vulkan/icd.d/intel_icd.json \
          /usr/share/vulkan/icd.d/intel_icd.json.disabled
  ```

- 如果只想枚举 PowerVR：

  ```bash
  VK_DRIVER_FILES=/usr/share/vulkan/icd.d/powervr_mesa_icd.json \
  PVR_I_WANT_A_BROKEN_VULKAN_DRIVER=1 \
  vulkaninfo --summary
  ```

## 13. Vulkan Compute 验证

使用仓库自带的 `tools/selftest.c`。本机未安装 `libvulkan-dev`，
因此临时使用了从 deb 解包的 Vulkan 头文件：

```bash
cd /mnt/luna-ssd/src/opi-bxm/ref-pvr-a733

cc -O2 -I/tmp/vkdev/usr/include -Itools tools/selftest.c \
   -o /tmp/pvr-a733-selftest \
   /usr/lib/aarch64-linux-gnu/libvulkan.so.1 -lm
```

如果系统已安装 `libvulkan-dev`，也可以直接：

```bash
cc -O2 -Itools tools/selftest.c -o /tmp/pvr-a733-selftest -lvulkan -lm
```

运行：

```bash
PVR_I_WANT_A_BROKEN_VULKAN_DRIVER=1 \
VK_DRIVER_FILES=/usr/share/vulkan/icd.d/powervr_mesa_icd.json \
/tmp/pvr-a733-selftest
```

本机结果：

```text
MESA: warning: Core count fetching is unimplemented. Setting 1 for now.
WARNING: powervr is not a conformant Vulkan implementation, testing use only.
pvr-a733-selftest: PowerVR B-Series BXM-4-64 MC1, 0/4096 wrong
```

`0/4096 wrong` 表示：

- Vulkan instance 创建成功
- physical device 选择正确
- device / queue 创建成功
- compute shader 提交并执行成功
- 计算结果校验通过

## 15. 注意事项

### 15.1 频率

当前使用：

```text
a733_clk_mhz=600
```

稳定后再尝试：

```bash
sudo modprobe -r powervr
sudo modprobe powervr a733_clk_mhz=800
```

1008 MHz 需要确认散热和电压。

### 15.2 Mesa 环境变量

当前 BXM-4-64 不在 Mesa conformant 列表中，应用运行前需要：

```bash
export PVR_I_WANT_A_BROKEN_VULKAN_DRIVER=1
```

登录 shell 可写入：

```bash
echo 'export PVR_I_WANT_A_BROKEN_VULKAN_DRIVER=1' | \
  sudo tee /etc/profile.d/powervr.sh
```

systemd 服务则在 unit 中设置：

```ini
Environment=PVR_I_WANT_A_BROKEN_VULKAN_DRIVER=1
```

### 15.3 Shared memory 已知问题

该 Mesa/GPU 组合存在 shared memory 相关问题：
**建议单个 workgroup 的 shared memory 控制在 2KB 以内**，超过可能触发
GPU lockup。

### 15.4 开机自动加载

当前模块是手动 `modprobe`。如需开机自动加载，可加入：

```bash
echo powervr | sudo tee /etc/modules-load.d/powervr.conf
```

但 GPU 驱动 bring-up 有挂死风险，建议使用 `ref-pvr-a733` 自带的
加载服务/启动保护，或确保有串口 console 和 watchdog 再启用自动加载。

### 15.5 显示

`powervr` 是 render-only 驱动：

- 提供 `/dev/dri/renderD128`
- 不接管 HDMI/显示
- 显示仍由 `sunxi-drm` 的 `/dev/dri/card0` 负责

### 15.6 内核升级

当前模块是手工安装到：

```text
/lib/modules/6.6.98-sun60iw2/updates/powervr.ko
```

内核升级后需要重新编译安装，或者使用 DKMS：

```bash
cd /mnt/luna-ssd/src/opi-bxm/ref-pvr-a733
sudo ./scripts/install.sh --dkms --clock 600
```

```bash
# 1. headers
sudo dpkg -i /opt/linux-headers-current-sun60iw2_1.1.0_arm64.deb
```
